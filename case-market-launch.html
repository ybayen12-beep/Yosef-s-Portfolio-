The situation: release management with no test system

Any mistake would land on the live system. The market had no test copy, the place where teams try changes before they go live. So every game install went straight onto the live system, which teams call production.

Every game also needed a record to track it from start to finish before launch day, which teams call go-live.

What I owned: go-live planning

I owned the launch plan for this market, from how the work was organised to the schedule the engineers worked to. I made sure every game had an install ticket, a tracking record and a due date I had checked.

The decision: one ticket standard

Standardization: I set one standard that every ticket followed, rather than leaving each ticket to be set up ad hoc. The standard covered how tickets were organised, how they were named and where their details came from.

Risk mitigation: with no test system, every install went straight to the live system. So I planned all 65 installs up front and spread them across 4 engineers over 5 working days.

How I ran it: resource scheduling and schedule re-planning

  1. Set the standard. I set how this market's tickets and tracking records were organised, how tickets were named and where their details came from.
  2. Planned every install. I planned 65 install tickets on the live system, 63 new and 2 reused, each with its own tracking record.
  3. Sequenced the work. I spread the installs across 4 engineers over 5 working days.
  4. Re-planned when the date moved. When the launch date moved, I re-planned and checked all 65 due dates rather than leaving the old schedule in place.
  5. Switched games on in one batch. I created all 31 tickets to switch games on in a single batch.
  6. Made it repeatable (process improvement). After launch, I turned the steps into 4 scripts, small programs that each run on their own, so the same setup could be repeated for this market.

The result

  • All 65 installs were planned on one standard, 63 new and 2 reused, across 4 engineers over 5 working days.
  • After the launch date moved, all 65 tracking records carried due dates I had re-planned and checked.
  • 31 tickets to switch games on were created in one batch.
  • The same setup can now run as 4 scripts for this market.
  • The markets I was responsible for grew from five in the U.S. plus one Canadian province to six in the U.S. plus the province.

I did not measure time saved by the scripts or the standard.
