I automated a deployment pipeline, then made sure it told the truth

Moving game updates out to each market meant manual ticket work for every market. Once I automated it, I found the bigger risk: a job could fail quietly while the dashboard said all was well.

The situation

Every game update had to be turned into tickets, scheduled, linked, tracked on a project board and reported back to the person who asked for it. People did each of those steps by hand.

My role

I'm the Project Manager, and I also designed and built the automations myself, using AI-assisted development.

What I did

  1. I built 24 scheduled Python automations connected to Jira and Monday.com. They took over ticket creation, scheduling, linking, board updates, status tracking and replies to requesters.
  2. In June 2026 I built an end-to-end game update automation that runs the full chain twice each weekday. I added a local operations console showing the pipeline, calendar, automations and alerts, with an audit trail, start-up self-checks and a read-only view. That view let a reviewing team trust the system without operating it.
  3. In the same month I cleaned up 1,220 orphaned tickets left behind by an older built-in rule.
  4. I then found a scheduler that did nothing while the dashboard showed it as healthy, because "healthy" only meant "ran without crashing". I paused the whole suite and audited 16 scripts. They shared three bug types: errors read as success, loose name matching, and failed work marked as done. I fixed the highest-risk scripts first and added a daily health check.
  5. I added safeguards against duplicate tickets across 7 workflows.
  6. In July 2026 I launched a close-out automation. Its first live run moved 21 records, and I verified each one.
  7. In August 2026 I found 7 games with 28 duplicate tickets, 11 of them scheduled so an older build would deploy last. I cancelled all 28 and verified them. The automation now cancels the replaced ticket itself and carries its date over to the new one.

The result

  • The audit surfaced 170 error lines, 165 failure lines and 15 crash traces that had been hidden in the logs.
  • A follow-up close-out pass checked 520 child items and closed 170, with 0 errors.
  • A daily health check now runs on the schedule alongside the automations.
  • One task still needs a person: rescheduling when two pieces of work clash. That's a judgement call, not a rule, so I left it with people.
